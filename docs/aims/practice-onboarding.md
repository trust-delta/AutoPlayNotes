# IS
「自動演奏」で探す人は練習したい人と別のセグメントではなく、**あきらめた同一人物**である、という読み。「私は弾けないし…」という妥協の産物としてその語を打ち込んでいる。だから自動演奏は捨てるターゲットではなく**拾えるターゲット**であり、窓が空のときの縮退形として練習と同じ機構の上に載っている（→ [[playable-reduction]]）。

プロダクトの仕事は、**説教しないこと**。妥協を否定せず、ただ隣に道が続いていることを見せる。

- **補助演奏**（窓の外だけをゲームへ送る）がこの aim の実体。「キーを送るからグレーだ、だから作らない」は、全自動の人には何も要求せず、**6 鍵を自分で弾こうとした人にだけ「それは提供できません」と言う**ことになる。自動に頼らない方向を向く、その姿勢を肯定できなければ、主軸の転換は看板の掛け替えでしかない。
- **建前は捨てない。** キーは飛ぶ。グレーであることは UI にも README にも正確に書く。自動演奏は消さない・隠さない・**アイデンティティにはしない**。目当てで使うのは自己責任。
- ⚠️ **伴奏や補助演奏を実装しても、それ単体では誰も練習を始めない。** 自動演奏で来た人に足りないのは肩代わりではなく**導線**である。機能を足したことで導線を作ったつもりにならない。
- ⚠️ **入口は UI より手前、名前から始まっている。** `AutoPlayNotes` という名が自動演奏を想起させるのは意図であって負債ではなく、改名しないことが決まっている（2026-09-09 / → [[shipping]]）。グレーを探して来た人がまずここへ辿り着き、そこから練習へ歩ける —— 「捨てるターゲットではなく拾えるターゲット」という読みは、看板の時点で既に効いている。
- ∴ **導線として足したのは機能ではなく「置き場所」と「間合い」だけ**である: 練習をタブの先頭に置き（起動時もそこ。ただし自分でタブを選んだ人にはその選択を優先する）、自動演奏が最後まで鳴りきった直後に一度だけ声を掛ける（同じ曲で二度は掛けない・断る側を既定に置く・黙らせる手段を同じ画面に置く）。判断は `onboarding.py` の純関数に出してテストで固定した —— この層は壊れても画面には出ているので、静かに元へ戻る。

# PROCESS
- [done] 補助演奏（窓の外だけをゲームへ送る。あなたのキー集合とアプリのキー集合が全曲を通じて素であることをテストで固定）
- [done] 自動演奏の自己責任スタンスを明文化（UI に ⚠️・README の後段へ移動）
- [done] README トップを練習主軸へ書き換え（演奏範囲を中心に、5 モードとキー送出の有無を表に）
- [done] タブ順と起動時のタブ（`🎮 練習` を先頭・起動時もそこ。前回開いていたタブは覚えて優先する。`onboarding.TAB_ORDER` / `startup_tab`）
- [done] 自動演奏が終わったら「この曲、弾いてみますか？」を出す（鳴りきったときだけ・同じ曲に 1 回・停止 / プレイリスト / 補助演奏では黙る。`onboarding.should_invite` ＋ `PracticeInviteDialog`）

# OBSERVATION
- 自動演奏を目当てに開いた自分が、起動時に `🎮 練習` タブが先に出ることを**案内として読める**か（押し付け・説教だと感じないか）
- 曲が鳴り終わったあとの誘いが、**その間合いで邪魔になっていない**か（聴き終えた直後に出る・断るのが一番簡単、になっているか）
- 誘いから「弾いてみる」を押した人が、演奏範囲の選択 → 練習モードまで**途中で詰まらずに到達**できるか
- 一度断った人が、自分から練習へ戻れるか（`🎮 練習` タブの入口だけで足りるか）
